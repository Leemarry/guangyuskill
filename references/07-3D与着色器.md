# 3D 与着色器

> `code/three/` 是第二种做法。它和 `Relay01` 的 2D 接力**不是新旧关系**，
> 是两种成本结构不同的工具。选错了会又慢又不好看。

## 一、两种做法怎么选

| | 2D 接力（`Relay01` + `Hero01`） | 3D（`World01` + `Hero02`） |
| --- | --- | --- |
| 依赖 | 只要 Remotion + React | 另加 `three` / `@react-three/fiber` / `@remotion/three`（约 40MB） |
| 单帧成本 | 极低，1050 帧约 2 分钟 | 高，受 GPU/软件渲染影响，实测见第五节 |
| 景深与体积感 | 靠雾和图层伪造 | 真的有 |
| 地貌之间怎么换 | **接力**，走过去就变了 | 默认按时间轴切场景（`cuts`），要连续就把 `World` 当外面一层的子组件塞进 `Relay01` |
| 适合 | 长镜头、慢推、一段 5–8 秒 | 卡点、快节奏、需要"一眼看到空间"的镜头 |
| 改一版的成本 | 改一行数组 | 要调 shader 或几何 |

判断方法：**如果需要观众"看清地形在空间中怎么转折"，用 3D；如果只需要"地面从脚下流过"，用 2D。**
2D 更省，而且连续过渡做起来更可控。

## 二、文件构成

```
code/three/
  shaders01.ts    四个 GLSL：天空、海面、点精灵、水母
  action01.ts     旅人轨迹 + 地形高度 + 镜头位姿（时间→位置的曲线表）
  Hero02.tsx      3D 旅人：LatheGeometry 袍身 + 逐顶点扰动斗篷 + 蝴蝶/蒲公英/风筝
  World01.tsx     3D 世界：七套色板 + 天空/海面/山/云/岛/纸船/火堆/彩虹
code/Stars01.tsx  星光：DOM 实现，不用 canvas
```

`Hero02` 与 `Hero01` 的取舍：`Hero01` 是 SVG 剪影，30 秒片子几秒渲完；
`Hero02` 有厚度、有景深、斗篷逐顶点飘动，但更慢。**同一个人物在两套做法里都只有一个实例**，
同行者用 `companion={1|2}` 复用同一套几何、只换取色与路线 —— 不要新建第二套模型。

## 三、四个着色器分别解决什么

| Shader | 为什么必须是 shader | 关键参数 |
| --- | --- | --- |
| `skyVertex/Fragment` | 天空要"云在动、地平线在呼吸"，用图片会有接缝和缩放模糊 | `time`、`night`（0 白天 / 1 夜）、`topColor`/`horizonColor` |
| `waterVertex/Fragment` | 海面要逐顶点起伏 + 菲涅尔亮带；用平铺贴图会在远处摩尔纹 | `time`、`beat`（低频能量）、`deepColor`/`lightColor` |
| `pointVertex/Fragment` | 几千个粒子要各自大小、各自相位、加性混合 | `time`、`beat`、`mode`、`pointScale` |
| `jellyVertex/Fragment` | 水母是半透明渐层 + 边缘发光，几何做不出来 | `time`、`phase`、`beat`、`tint` |

三条 shader 纪律：

1. **时间用 uniform 传，不要在 shader 里读 `performance.now()`** —— 那样每次渲染同一帧结果都不同，无法重渲。
2. **`beat` 由调用方传入**。`World01` 不自己读 json，数据来源交给上层决定，换曲子不用改组件。
3. **加性混合要关 `depthWrite`**，否则后面的粒子会被前面的"挡住"，出现方块状黑洞。

## 四、Remotion 里的三个必要设置

```tsx
<ThreeCanvas
  width={width} height={height}                    // 必须显式给，不能用 CSS 撑
  gl={{antialias: true, alpha: false,
       preserveDrawingBuffer: true,                // 不开就抽不到帧
       powerPreference: 'high-performance'}}
  dpr={1}                                          // 关键：见下
/>
```

- **`dpr={1}`**：默认按设备像素比渲染，1920×1080 在 2× 屏上等于渲 3840×2160，
  慢 4 倍且最终视频还是 1080p。**这一行不改，渲染时间会莫名其妙翻几倍。**
- **`preserveDrawingBuffer: true`**：不加，Remotion 截图会得到黑帧（canvas 已被清空）。
- **`width/height` 显式传**：`ThreeCanvas` 不会自己量父容器。

## 五、成本（实测）

| 项 | 值 |
| --- | --- |
| 依赖体积 | `three` + fiber + remotion/three 约 40MB（`node_modules` 增量） |
| 3D 60 帧 | **28 秒**（含约 8 秒启动/打包），折算 0.33 s/帧 |
| 2D 1050 帧 | 128 秒，折算 0.12 s/帧 |
| 结论 | 3D 单帧成本约为 2D 的 **2.7 倍**。30 秒片子 3D 约 5 分钟、2D 约 2 分钟 |
| 建议 | 先用 `--frames a-b` 只渲一段验证构图，别一上来渲全片 |

`World01` 的粒子数是有讲究的：`mode=0`（星尘）320–1400 个，
`mode=1`（深海光点）14500 个 —— 那一段是"光的密度"本身在讲故事，粒子少了就不成立。
其余场景不要照抄 14500，会白白拖慢。

## 六、它**不满足**本技能的核心约束（必须知道）

`ThreeDemo` 是拿 `cuts` 硬切场景的。实测跑验收：

```
相邻帧最大亮度差    FAIL   126.6（第 116 帧 / 3.87s）   阈值 ≤ 8
转场中心最大比      FAIL   18501.45（第 639 帧）        阈值 < 1.4
```

**这不是 qc 的误报，是它判对了。** 3D 版这个示例的本质是"七段卡点"，不是连续过渡。
所以定位要清楚：

| 你要的 | 用哪个 |
| --- | --- |
| 走着走着就换了世界（本技能的主线） | `Demo` / `Relay01` + 2D 地貌 |
| 卡点、快节奏、每段换一个世界（允许切） | `ThreeDemo` / `World01` |
| 既要 3D 的体积感，又要连续 | 把 `World` 关掉内部换场（固定 `sceneOverride`），让 `Relay01` 去接力 —— 见第七节 |

这也是 `qc.py` 存在的意义：它不看你自己的解释，只看那一帧跳了多少。

## 七、从别的工程移植时改了什么（重要）

这个变体来自另一个同样做"光遇"的工程。移植时做了三处**必须做**的改动，
否则它只是一个能跑但不可复用的组件：

| 原状 | 问题 | 改法 |
| --- | --- | --- |
| `World.tsx` 里 `import analysis from './audio-analysis.json'`，用 `analysis.bass[frame]` | 组件与某一首曲子绑死，换曲子必须改源码 | 改成 `beat` 入参，数据由调用方给（`beatmap.py` 产出的 `bass_out`） |
| `SkyStars.tsx` 是独立 DOM 组件，样式写死 | 与技能里已有的星点重复 | 合并成 `Stars01`，抽出 `from/to/count/flash/tint` 四个参数 |
| 场景切换用 `cuts` 硬下标 + `findIndex` | 一旦帧率不是 30 就全错 | `cuts` 保留（它是"这一段多少帧"的表格），但注释里明确：**帧率变了要按秒重算** |

还有一个不建议照抄的地方：`World01` 的 `Foreground` 用 `edge` 公式生成前景边缘，
在某些帧会读成"一块平面盖在海上"。如果要修，改 `Foreground` 里
`const edge = 1.5 + Math.sin(v*7)*1.2 - v*1.4;` 这条曲线，让它随场景变化，
而不是全程同一条。

## 八、把 3D 塞进连续过渡

`World` 只在最外层包了一个 `ThreeCanvas`，内部 `WorldScene` 是普通 R3F 组件。
所以有两种接法：

```tsx
// A. 让 3D 成为"某一段地貌"
<Relay01 scenes={[..., {render: () => <World fixedFrame={f} sceneOverride={2} beat={beat} />}]} />

// B. 3D 做底，2D 叠在上面（雾、文字、光斑）
<AbsoluteFill>
  <World beat={beat} />
  <MistBand01 kind="cool" sec={sec} from={0} to={35} tint={tint.mist} />
</AbsoluteFill>
```

A 的关键是 `fixedFrame`：一旦 3D 场景被放进 `Sequence`，
`useCurrentFrame()` 拿到的是**段内帧**，而 `action01.ts` 的曲线表是全片时间。
传 `fixedFrame` 才是全片时间轴 —— 这一条错了，人会从错误的起点开始走。
