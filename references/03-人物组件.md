# 人物组件：一个代码块，不是一个角色

## 一、为什么要单独抽出来

人物是这类片子里最容易写坏的部件，因为它同时承担三件事：

1. **连续性证据**：观众判断"这是同一个人"靠的是他一直在、且变得合理。
   如果每段各画一个，"变得合理"就无从谈起。
2. **时间标尺**：身高、步频、体态是观众读"过了多久"的唯一线索。字幕说"二十年"没有用，
   他矮下去、慢下来才有用。
3. **性能**：一帧里出现 10 个人物很常见（主角 + 路人 + 孩子群），
   如果每个人的绘制都很贵，渲染时间会失控。

所以它不是"一个角色的美术资源"，是**一个用参数驱动的绘制函数**。
角色是这个函数的一次调用。

## 二、造型的四条要点

少任何一条，它就从"光遇式小人"退化成"一根药丸"：

| 要点 | 做法 | 少了会怎样 |
| --- | --- | --- |
| 头与身分离 | 头椭圆比斗篷窄，中间留出颈部空隙 | 头和身体黏成一块水滴 |
| 斗篷是 A 形 | 肩口窄（rx 23）、下摆宽（hemW 32），下缘带弧度 | 变成直筒睡袋 |
| 头顶一盏烛光 | 小光核 + 大光晕 + 每帧 flicker | 在逆光里立不住，像贴纸 |
| 腿是两段折线 | 髋 → 膝 → 脚，膝点有偏移（+3px） | 腿是两根直棍，跑步没有腾空感 |

另外两个容易被忽略的细节：

- **接触阴影**：脚下必须有一片 `rgba(6,4,10,0.34)` 的椭圆。没有它，人站在坡上会显得悬空。
- **逆光轮廓**：沿斗篷右缘和头部描一道 `rgba(255,210,156,0.52)` 的细线。
  这是"人站在光里"最省的表达方式，比加高光便宜得多。

造型在 `code/Figure01.tsx` 的 `FigSvg` 里，viewBox 固定 `120 × 200`。
所有坐标都是这个坐标系内的绝对值 —— 换尺寸只改 `h`，内部不用动。

## 三、参数表（HeroPose）

| 字段 | 范围 | 含义 | 典型值 |
| --- | --- | --- | --- |
| `x` | 0–1 | 屏幕横向位置（中心） | 0.2 → 0.55 |
| `foot` | 0–1 | 脚底在画面高度的位置 | 0.76 → 0.845 |
| `h` | px | 身高 | 150（童年）→ 215（壮年）→ 185（老年） |
| `cadence` | 步/秒 | 步频 | 2.05（小跑）→ 0.3（拄杖） |
| `stride` | 0–1.2 | 步幅系数 | 1.15 → 0.16 |
| `hunch` | 0–1 | 驼背：头前塌 + 肩上抬 + 下摆收窄 | 0 → 0.88 |
| `tilt` | 度 | 上身前倾 | 6（小孩前冲）→ 4（中年）→ 10（老年） |
| `look` | −1–1 | 转头（负值向右） | 0，偶发 −1 |
| `prop` | `lamp` / `staff` / `null` | 持物：提灯 / 杖 / 空手 | 全片切 2 次 |
| `glow` | 0–1 | 自发光强度 | 1 → 0.7 |
| `turn` | −1–1 | 转身：1 正面，0 侧面，−1 背面 | 只在一次回头时变 |
| `mode` | `run`/`walk`/`idle`/`sit` | 姿态模式 | 跑 → 走 |

`turn` 和 `mode` 是两个独立的东西：`turn` 管朝向（用 scaleX），`mode` 管动作库。
26 秒时"停下 → 转身 → 改为走"，这三个动作叠在雾最浓的 1 秒里，看不见接缝。

## 四、六条曲线怎么定

曲线不是随手拉的，每条对应一个观众能读到的信息：

| 曲线 | 变化 | 观众读到 |
| --- | --- | --- |
| `height` | 150 → 215 → 185 | 长大，然后老去 |
| `cadence` | 2.05 → 0.3 | 从跑不动到走不快 |
| `hunch` | 0 → 0.88 | 背越来越驼 |
| `stride` | 1.15 → 0.16 | 步子越来越小 |
| `tilt` | 6 → 4 → 10 | 小孩往前冲，老人往前探 |
| `turn` | 1 → 0 → −1 | 他回过头看了一眼来路 |

写法用**分段 smoothstep**（`kf()`），不用线性：线性插值在斜率不同的节点会留下折角，
慢动作里能看见。smoothstep 保证每个关键帧处一阶导为零。

曲线密度也有讲究：变化快的地方（12–16 秒长个子）关键帧要密，
稳定期（0–6 秒童年）两三个点就够。全片 12–14 个关键帧是舒服的量。

## 五、步态相位：最容易出错的一处

**不要用 `t × cadence` 算相位。**

人物内部是 `sp = t · 2π · cadence`。当 cadence 从 2.05 降到 0.30 时，
`t × cadence` 会在减速段**倒退**：

```
26s: 26 × 0.92 = 23.9
27s: 27 × 0.88 = 23.8   ← 比上一秒还小
```

腿会倒着抽 —— 这是最容易被误判成"渲染 bug"的一个坑。

正确做法是把 `∫cadence dt` 预先积出来当"时间"传给人物，人物的 `cadence` 固定为 1：

```ts
const phaseAt = makePhase(curves.cadence, duration);   // 内部按 1/240 秒积分
<Hero01 pose={pose} phase={phaseAt(sec)} />
```

于是减速自然变成"步子越来越慢"，而不是抽搐。

## 六、转身：用 scaleX，不改 dir

```tsx
transform: `translate(-50%,-100%) scaleX(${turn})`
```

`turn` 从 1 连续到 −1，中间经过 0 —— 那一帧宽度为零，正好是侧面轮廓。
示例把这个时刻安排在 26 秒的雾里，所以"回头"是一个动作，不是一个开关。

**为什么不能改 `dir`**：`dir` 参与逐点几何计算（腿的 fx、手的 handX、驼背的 hx 都乘了 dir），
它只能取 ±1。如果让 dir 在帧间从 1 跳到 −1，腿的折向会在那一帧整体翻面，
出现"两条腿交叉"的瞬间。

`turn` 过 0 附近要跳过绘制（`Math.abs(turn) > 0.03`），否则会渲染一条零宽的线。

## 七、编号约定与新增角色

一个文件一个人物：`Hero01` / `Hero02` / `Hero03` …

```
code/Figure01.tsx   造型基座（FigSvg 的绘制实现）
code/Hero01.tsx     人物 01 = 造型选择 + 默认曲线 + 摆位
code/pose01.ts      曲线机制（makeHero / makeCamera / makePhase）
```

新增角色时：

1. 复制 `Hero01.tsx` → `Hero02.tsx`，改导出名为 `Hero02` / `Hero02Walk`
2. 改造型参数（tint / rim / 比例）与默认曲线（如果新角色有自己的生命周期）
3. **不要改 `Hero01.tsx`** —— 已经在用它的片子不该因为别人加了角色而变样

如果新角色的**造型**也不同（不是斗篷小人，比如一只鹿），有两种做法：

- 简单：`Hero02` 自己写一个 svg，只要接收 `HeroPose` 就能复用整套曲线机制
- 复用：给 `FigSvg` 加 `kind` 参数，但会让 01 的文件越来越复杂，不推荐超过 2 种

## 八、常见错误

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 腿在减速段倒着抽 | 用了 `t × cadence` | 改用 `∫cadence dt` |
| 转身那一帧人变成一条竖线 | 没跳过 `turn ≈ 0` | `abs(turn) > 0.03` 才画 |
| 人站在坡上像悬空 | 没有接触阴影 | 脚下加暗椭圆 |
| 人物在逆光里像贴纸 | 没有 rim 轮廓线 | 沿右缘描 1.6–1.9px 暖线 |
| 头看起来比身体还宽 | 头椭圆 rx 太大 | 15.5 是上限，且斗篷下摆要更宽 |
| 减速时整个人在发抖 | `hunch`/`tilt` 曲线用了线性插值 | 改 `kf()` 的 smoothstep |
